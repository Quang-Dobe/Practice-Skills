# Internationalization

> Load when: translations, locales, i18n, react-i18next, FormatJS / react-intl. Pinned: React 19.3, Vite 8, React Compiler 1.0, React Router 8.

## Existing repo
- How to recognise it: `i18next`/`react-i18next` (`useTranslation`, `Trans`, `locales/*/*.json`) or `react-intl` (`IntlProvider`, `FormattedMessage`, `useIntl`, ICU messages).
- Rule: follow what is there. FormatJS / react-intl stays (ICU messages, `FormattedMessage`, `useIntl`); never migrate one library to the other unasked. Match its key style and file layout.

## New repo default
- react-i18next on top of `i18next`: one `i18n.ts` calling `i18n.use(initReactI18next).init(...)`, imported once before render.
- One namespace per feature (`features/<name>` ↔ `<name>.json`); resources are JSON per language and namespace, loaded lazily (dynamic import or a backend plugin) instead of bundled.
- `useTranslation('<ns>')` and `t('key')`; interpolation with `{{name}}`; plurals via `count` with `_one`/`_other` keys.
- `Trans` for markup or components inside a sentence, so translators see one string.
- Dates, numbers, relative time and lists through `Intl` (`DateTimeFormat`, `NumberFormat`, `RelativeTimeFormat`, `ListFormat`) with the active locale, not manual formatting.
- Every new user-facing string goes through `t` from the start, including `aria-label` and `title`.

```tsx
import { Trans, useTranslation } from 'react-i18next';

// en/inbox.json: { "unread_one": "{{count}} unread message",
//   "unread_other": "{{count}} unread messages",
//   "hello": "Hello <1>{{name}}</1>, welcome back." }
export function Inbox({ name, count }: { name: string; count: number }) {
  const { t, i18n } = useTranslation('inbox');
  const when = new Intl.DateTimeFormat(i18n.language, { dateStyle: 'medium' }).format(new Date());
  return (
    <section>
      <p>
        <Trans i18nKey="hello" ns="inbox" values={{ name }} components={{ 1: <strong /> }} />
      </p>
      <p>{t('unread', { count })}</p>
      <time>{when}</time>
    </section>
  );
}
```

## Avoid
- Concatenating sentence fragments (`'You have ' + n + ' items'`) → word order and plurals differ per language → one key with interpolation and `count`.
- Hard-coded user-facing text in new components → untranslatable later → `t('key')`.
- Hand-formatting dates and numbers → wrong per locale → `Intl` with the active locale.
- Splitting a sentence around markup → translators lose context → `Trans`.
- Switching an existing react-intl app to react-i18next unasked → needless churn → keep its ICU messages.
